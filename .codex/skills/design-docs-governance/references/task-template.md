# Task 文档模板

`design-docs/Task.md` 是设计文档的总入口，负责说明项目当前大功能迭代的方向、拆分、进度和验收状态。它面向产品、开发、设计和 Agent，不只面向代码实现者。

## 推荐结构

```markdown
# {项目或迭代名称} Task

## 目标

- {用一句话说明本次迭代要解决的问题}
- {说明成功后的用户或业务结果}

## 当前状态

- 状态：{未开始 / 设计中 / 开发中 / 待验收 / 已完成 / 阻塞}
- 负责人：{人或 Agent}
- 最近更新：{YYYY-MM-DD}
- 唯一入口：{代码入口、产品入口、命令入口或设计入口}

## 设计拆分

| 模块       | 设计文档     | 状态   | 进度说明   |
| ---------- | ------------ | ------ | ---------- |
| {模块名称} | `{相对路径}` | {状态} | {当前进展} |

## 开发顺序

1. {第一阶段要完成的设计或实现}
2. {第二阶段要完成的设计或实现}
3. {第三阶段要完成的设计或实现}

## 阻塞与风险

| 问题             | 影响       | 下一步     |
| ---------------- | ---------- | ---------- |
| {待确认或风险点} | {影响范围} | {处理动作} |

## 验收总览

- 产品验收：{通过标准}
- 开发验收：{通过标准}
- 设计验收：{通过标准}
- Agent 验收：{文档、代码、测试和进度是否一致}

## 变更记录

| 日期         | 变更       | 原因       |
| ------------ | ---------- | ---------- |
| {YYYY-MM-DD} | {变更内容} | {变更原因} |
```

## 写作要求

- `Task.md` 必须能单独说明当前迭代正在做什么。
- 每个设计拆分项都要链接到具体子设计文档。
- 状态变更必须有依据，不能只写“完成”。
- 唯一入口必须可定位，优先写相对路径、命令、路由或用户操作入口。
- 阻塞项要写下一步动作，避免只记录问题。
